# 验证样例

## 初始状态

- 应用「临港书店店员」已按 README.md 第四节完成部署、导入、知识库创建与重新绑定，并已发布。
- 知识库内容为 `临港书店.txt`，索引已存入 seekdb 的 `dify_vector` 库，知识检索节点召回条数为 4。
- 应用不使用会话记忆和预置记忆，**每个问题都新开一轮对话**，各轮互不影响，无需恢复初始状态。

## 操作步骤

1. 打开应用入口：Dify 工作室 → 「临港书店店员」→ 预览（或发布后的 WebApp 链接）。
2. 依次输入下表中的问题，每输入一问前先新开一轮对话。
3. 核对回答内容，并展开「引用」确认来源为「临港书店.txt」。

## 验证用例

| 序号 | 输入 | 预期回答 | 证据 |
|---|---|---|---|
| 1 | 今天的推荐是什么？ | 《海边的灯塔》58 元，《数据库入门》79 元 | 今日推荐.png |
| 2 | 会员日折扣和满减一起用吗？ | 不能叠加，取对顾客更优惠的一种 | 会员规则.png |
| 3 | 店里有没有咖啡？ | 这个问题我要问一下店长（资料中没有的内容不编造） | 店里有没有咖啡.png |

用例 3 用于验证「资料里没有答案时不编造」的行为；开放式提问没有唯一标准答案，回答语义一致、不出现编造信息即视为通过。

## seekdb 作用验证

seekdb 只承载知识库向量存储。知识库索引完成后，连接 seekdb（端口 2881）执行：

```sql
USE dify_vector;
SHOW TABLES;
```

预期看到一张以 `vector_index_` 开头的表（见 `seekdb表.png`）：

- 该表由 Dify 索引 `临港书店.txt` 时**写入**；
- 上表 3 个用例问答时，由「知识检索」节点从该表**读取**向量并召回片段；
- 回答下方的「引用」显示来源为「临港书店.txt」，即检索结果来自 seekdb 中的向量数据。

以上可证明 seekdb 在应用运行中实际承担数据存储与检索职责，而非仅安装未用。
