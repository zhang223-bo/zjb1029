## 设计要点

1. **两段式数据链**：`maps_around_search` 拿候选 POI，`maps_direction_walking` 拿真实步行距离与耗时；POI 自带 `distance` 与 `maps_distance` 只作初筛，禁止替代步行路线（题目硬性要求）。
2. **半径估算**：步行上限 × 80 米（下限 500、上限 3000），并明确“直线半径内的点仍可能超时”，因此逐点做路线校验；候选不足时按 1.5 倍扩一次并在说明中写清扩大范围。
3. **硬条件执行**：超时用原始秒数与“上限 × 60”比较，超时点直接淘汰、不作为“备选”暗示；数量上限 3 不可破。
4. **抗工具名漂移**：高德 MCP 存在 `maps_direction_walking` / `maps_direction_walking_by_coordinates` 等命名差异，Skill 按“能力”匹配工具，避免评测环境版本差异导致调用失败。
5. **单轮不卡反问**：平台会直接给出起点坐标，拿到即用、不重新地理编码；缺坐标时先用城市 + 描述词检索并声明近似起点，不阻塞在追问上。
6. **真实性护栏**：地点/地址/坐标必须来自工具返回；理由只引用可核验字段；营业、排队、安静程度统一标“未核实”；无结果与接口异常如实说明并给一句放宽建议。
7. **调用预算**：周边搜索 ≤2 次、步行路线 ≤8 次、详情仅对入选点查询，兼顾时延与覆盖。
