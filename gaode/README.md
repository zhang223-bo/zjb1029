## 设计要点

1. **两段式数据链**：`maps_around_search` 拿候选 POI，`maps_direction_walking` 拿真实步行距离与耗时；POI 自带的 `distance` 与 `maps_distance` 只用于初筛，禁止替代步行路线（题目硬性要求）。
2. **半径估算**：步行上限 × 80 米（下限 500、上限 3000），并说明“直线半径内的点仍可能超时”，因此必须逐点做路线校验。
3. **抗工具名漂移**：高德 MCP 存在 `maps_direction_walking` / `maps_direction_walking_by_coordinates` 等不同命名，Skill 按“能力”匹配工具而非硬编码名字，避免评测环境版本差异导致调用失败。
4. **单轮不追问**：时间上限、数量、排序、起点缺失时取默认值并在回答中声明，避免评测单轮任务卡在反问。
5. **真实性护栏**：地点/地址/坐标必须来自工具返回；超时点不列为符合条件的推荐；安静程度、排队、营业状态等无依据信息统一标“未核实”；查询失败与结果不足如实说明并给放宽建议。
6. **调用预算**：周边搜索 ≤2 次、步行路线 ≤8 次、详情 ≤3 次，兼顾时延与候选覆盖。
